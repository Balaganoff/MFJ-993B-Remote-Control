# MFJ-993B Companion 1.3.0 — Main Capture Recovery

Это комплект из прошивки ESP32 и компактного Win64-клиента. За основу взят
текущий рабочий файл из ветки `main` репозитория MFJ-993B Remote Control.

## Что не менялось в захвате

- `SAMPLE_DELAY = 90`;
- в декодер по-прежнему всегда идёт `s1`;
- `s2` остаётся только диагностикой;
- несовпадение `s1/s2` не удаляет полубайт;
- цикл ожидания `E`, сборка обычной пары nibble и Web LCD сохранены.

## Что добавлено

Перед каждым непрерывным участком шины с одним значением `RS` прошивка хранит
последний подтверждённый снимок DDRAM/CGRAM. Если на смене `RS` или после
паузы остаётся один непарный nibble, число импульсов в участке нечётное.
Такой участок откатывается целиком, а адрес данных блокируется до следующей
настоящей команды `Set DDRAM/CGRAM Address`.

В результате один потерянный или лишний импульс больше не оставляет
виртуальный LCD навсегда сдвинутым. Клиенты продолжают видеть последний
хороший кадр, а следующий корректный участок принимается автоматически.

Кнопка `RESET LCD` теперь отправляет отдельную команду `R`. Она:

- не очищает видимый экран;
- не меняет ни один GPIO кнопок;
- не выключает и не включает тюнер;
- откатывает текущий участок и ждёт безопасную границу `RS` либо паузу шины.

Автоматический rollback находится в ESP32, поэтому он одинаково работает и
для браузера, и для Win64 Companion.

## Установка прошивки

Файл для OTA:

`firmware/MFJ993B_Remote_Control_main_recovery_v1.ino.bin`

Его можно передать через `CONFIG -> ПРОШИВКА .INO.BIN` либо через страницу
`http://IP_ESP/update`. После перезапуска открыть:

`http://IP_ESP/status`

Поле `firmware` должно быть:

`2026.10.01-main-capture-recovery-v1`

Поле `run_rollbacks` увеличивается только когда прошивка обнаружила и
откатила нечётный участок. `manual_recoveries` считает команды `RESET LCD`.

## Запуск Win64 Companion

1. Полностью распаковать ZIP в обычную папку.
2. Запустить `START_CLIENT.bat`.
3. При первом запуске вложенный официальный Python x64 тихо разворачивается
   в локальную подпапку `.python-runtime`; интернет и установленный Python не
   требуются.
4. В `CONFIG` проверить IP и нажать `ПЕРЕПОДКЛЮЧИТЬ`.

Основные экраны и страницы `MODE` обрабатываются так же, как в принятой
версии Companion 1.1.1; менялась только команда восстановления.

## Важное ограничение пассивного перехвата

ESP32 не может прочитать символы, которые PIC уже отправил до ошибки и больше
не повторяет. Поэтому повреждённый участок не угадывается: остаётся последний
хороший кадр, а недостающие позиции обновятся при следующей обычной передаче
PIC. Это безопаснее, чем записывать сдвинутые байты и портить все экраны.

## Проверки

- PlatformIO: успешная сборка ESP32;
- модель нормального потока: результат не изменён;
- модель с потерянным nibble: плохой участок откатывается, следующий экран
  принимается;
- 12 тестов Companion: кнопки, MODE-экраны, WebSocket и безопасный `R`;
- тест подтверждает, что `void loop()` захвата побайтно совпадает с `main`.
